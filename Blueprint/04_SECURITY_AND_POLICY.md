# 04 — Security and Policy

## 1. Threat model

AECP is powerful local software and must assume:
- task text can contain malicious/prompt-injected instructions;
- repositories may contain hostile instructions/scripts;
- shell commands can destroy data;
- browser content is untrusted;
- API keys are high-value secrets;
- a compromised provider must not automatically gain unrestricted local control.

Therefore provider reasoning is never the security boundary. The Local Policy Engine is.

## 2. Trust boundaries

1. Official ChatGPT/browser — external, untrusted as an execution principal
2. Renderer UI — untrusted presentation context
3. Preload bridge — narrow validated IPC surface
4. Main/Harness process — trusted local control plane
5. Workspace filesystem — user-authorized scope
6. External network/GitHub — explicit capability
7. Credential store — privileged secret boundary

## 3. Electron baseline

Mandatory:
- `contextIsolation: true`
- `nodeIntegration: false`
- renderer sandbox enabled
- no `remote` module
- strict IPC allowlist
- validate every IPC argument in main process
- deny arbitrary navigation
- deny unsolicited window creation
- external URLs opened through OS browser only after scheme validation
- no privileged preload attached to remote ChatGPT origin
- Content Security Policy on local UI

## 4. Risk classes

### GREEN
Read-only local inspection:
- tool detection
- list workspace/repositories
- git status/log/remote read
- read explicitly bound files
- local search/index

Runs after explicit user initiation.

### YELLOW
Reversible workspace mutation:
- write/modify files inside workspace
- install project dependencies
- run arbitrary project commands
- create branch/worktree
- git commit
- controlled desktop interaction

Requires action preview and approval unless a workspace policy explicitly pre-authorizes the exact capability.

### RED
High-impact:
- delete
- git push/publish/release
- credential use
- actions outside workspace
- system settings
- admin/elevation
- payment/billing
- security configuration

Always explicit approval in bootstrap. Some are hard-denied.

## 5. Policy as code

Example:

```yaml
version: 1
workspace: alpha
filesystem:
  roots:
    - D:\Alpha
  read: allow
  write: ask
  delete: deny
shell:
  readOnlyCommands: allow
  arbitrary: ask
git:
  status: allow
  commit: ask
  push: always_ask
  forcePush: deny
network:
  default: ask
system:
  admin: deny
```

UI edits must compile to this canonical policy representation.

## 6. Path safety

Every filesystem/command working-directory request:
1. canonicalize path;
2. resolve junction/symlink implications when possible;
3. confirm it is within an authorized root;
4. reject UNC/network paths unless policy explicitly allows them;
5. never trust path strings supplied by a provider alone.

## 7. Command safety

Bootstrap engine maintains:
- explicit cwd
- timeout
- output limit
- cancel
- process-tree termination best effort
- dangerous-command deny patterns as a secondary guard
- risk preview to user

Pattern blocking is defense-in-depth, not the primary policy mechanism.

## 8. Credentials

Secrets must not appear in:
- project files
- Git commits
- traces
- Result Capsules
- clipboard result payloads
- logs

Use OS-protected encryption and opaque references. Provide Delete Credential and Rotate guidance.

## 9. ChatGPT boundary

AECP must not:
- inject scripts into chatgpt.com
- scrape messages automatically
- copy session cookies/tokens
- call reverse-engineered ChatGPT private APIs
- intercept browser TLS/traffic
- attempt to circumvent rate limits or product restrictions

Safe Bridge is an explicit clipboard/user-gesture protocol. Clipboard is read only when the user presses Import.

## 10. Updates and supply chain

- lock dependencies with `package-lock.json` once generated by CI/developer environment
- GitHub Actions permissions minimal
- release hashes generated
- code signing strongly recommended before public distribution
- unsigned bootstrap builds must be labeled clearly; Windows SmartScreen warnings are expected without Authenticode reputation
- dependencies and licenses audited before stable release

## 11. Privacy defaults

- no telemetry in bootstrap release
- no analytics SDK
- evidence stored locally
- no automatic upload of source/evidence
- settings expose all network-capable adapters
