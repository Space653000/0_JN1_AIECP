# Owner-external gates: operator runbook

This is a preparation and evidence checklist, not a record of completed acceptance. The four gates below remain **OWNER-EXTERNAL / NOT DONE** in [STATUS](../.ai/STATUS.md). The owner must not paste credentials, private keys, tokens, internal URLs, prompts, or responses into this repository or an evidence JSON. Record only artifact filenames, SHA-256 digests, run URLs, and non-secret conclusions. Example values below are `<placeholder>`.

## 1. Authenticode signing and owner-authorized release

- **Owner prerequisite:** control a production code-signing certificate/private key and know its public certificate thumbprint; approve the release/version and whether publishing is allowed. Keep the PFX/private key outside the repository.
- **Repository secrets actually referenced:** `AECP_CODESIGN_PFX_BASE64`, `AECP_CODESIGN_PASSWORD` in [signed-release.yml](../.github/workflows/signed-release.yml). Set through the repository's owner-controlled secret management, never a tracked file.
- **Trigger:** manually dispatch **AECP Signed Release** with `source_ref=<placeholder>` (exact source commit/tag), `release_tag=<placeholder>` (must equal `v` + `package.json` version), `signer_thumbprint=<placeholder>`, `publish_ack=false` for artifact preparation. Set `publish_ack=true` only after explicit owner approval; only then the gated publish job uses write permission to attach assets to a GitHub Release. Do not treat a dry run as a published release.
- **Expected evidence:** `aecp-signed-x64`, `aecp-signed-arm64`, `aecp-signed-universal`, and `aecp-signed-release-bundle` artifacts; the bundle contains `SHA256SUMS.txt` and `SIGNED_RELEASE_PROVENANCE.json`. Compare downloaded files' SHA-256 with the manifest; inspect `authenticode-{arch}.json` / `authenticode-universal.json` and independently verify `Get-AuthenticodeSignature` status and signer thumbprint. The workflow embeds `aecp.requiredSignerThumbprint` in its build; [authenticode.cjs](../electron/lib/authenticode.cjs) implements the runtime signer pin. Record the exact run URL and source SHA, not a certificate private key.
- **Failure / rollback:** if input, verification, signature, or hash checks fail, stop distribution and leave `publish_ack=false`; correct the owner-side certificate/secret or inputs and run again. If already published, owner must halt distribution and use an explicit release-management decision; the repository has no automatic recall/rollback procedure for a signed public release.
- **缺口:** certificate issuance/ownership, timestamp-chain trust on real consumer devices, external release authorization, and post-publication recall cannot be proven by the repository workflow alone. Keep this gate open until owner evidence is reviewed.

## 2. Microsoft Store / Partner Center

- **Owner prerequisite:** own a Partner Center app reservation and exact Package Identity Name, Publisher, and Publisher Display Name; control submission, certification, Private Audience membership, and a clean-device acquisition account. The values must match Partner Center, per [Store README](../release/store/README.md) and [metadata template](../release/store/store-metadata.template.json).
- **Repository secrets actually referenced:** none by [store-package.yml](../.github/workflows/store-package.yml). Do not invent a Partner Center token or commit identity credentials.
- **Trigger:** manually dispatch **AECP Store Package** with `identity_name=<placeholder>`, `publisher=<placeholder>`, `publisher_display_name=<placeholder>`, and `private_audience_ack=true`. This acknowledgement confirms that the workflow builds artifacts **only**; it never submits to Partner Center.
- **Expected evidence:** x64/ARM64 `aecp-store-owner-{arch}` artifacts and `aecp-store-submission-bundle` with `SHA256SUMS-store.txt`, `STORE_PROVENANCE.json` (`submittedToPartnerCenter=false`), packages, and `store-evidence-{arch}.json`. Compare downloaded SHA-256 values. [validate-store-package.ps1](../scripts/validate-store-package.ps1) checks package identity, publisher, architecture, executable, `runFullTrust`, and hash. Owner separately records Partner Center submission/certification and clean-device Private Audience acquisition evidence; do not confuse the preparation artifact with certification.
- **Failure / rollback:** do not submit packages with mismatched identity/hash or failed validation. Correct the owner identity or build inputs and rerun. If a submission fails certification, use Partner Center's owner-controlled resubmission/withdrawal process; no repository automation does that.
- **缺口:** app reservation, Partner Center submission/certification, audience assignment, acquisition and publisher-trust proof on a real clean device remain external.

## 3. Optional public/LAN Remote Gateway

- **Owner prerequisite:** choose/control a domain or LAN endpoint, device identities, TLS certificate/private key or PFX, deployment host, and an access policy. Do not place key material or an internal URL in evidence. [remote-gateway.cjs](../electron/lib/remote-gateway.cjs) defaults to `127.0.0.1`; a non-loopback bind requires both `allowRemote=true` and valid TLS. [pairing.cjs](../electron/lib/pairing.cjs) limits pairing to expiring `READ_ONLY` / `APPROVAL_ONLY` scopes and supports revocation.
- **Repository secrets/workflow inputs:** no dedicated remote-deployment workflow or referenced repo secret/input exists. **缺口:** there is no repository-owned workflow trigger to cite; do not treat a local gateway launch as a production deployment.
- **Success evidence:** owner-operated TLS endpoint and device pairing/revocation records, `/health` showing secure remote configuration, read-only status/events and approval-only behavior, negative unauthorized-access tests, exact code SHA, and non-secret digests of deployment configuration. Do not record pairing codes/tokens. The gateway does not expose remote task submission or general write capability.
- **Failure / rollback:** disable non-loopback exposure, revoke paired devices and rotate owner-controlled TLS/token material where applicable; restore loopback-only operation. Never broaden the SecurityPolicy or pairing scope to make a test pass.
- **缺口:** domain ownership, network perimeter/TLS operations, public/LAN deployment, real-device trust and incident response require an owner-managed environment and an approved deployment procedure not present in this repository.

## 4. Formal production-provider claims

- **Owner prerequisite:** a real supported provider account/runtime, model files where relevant, authorized credentials, architecture-matched self-hosted runner, and product/workspace entitlements. Keep OFFICIAL auth in its existing isolated home and PEGA credentials in owner-controlled environment secrets; never copy/overwrite auth files. The evidence procedure is [ENVIRONMENT_EVIDENCE_RUNBOOK](ENVIRONMENT_EVIDENCE_RUNBOOK.md), with acceptance criteria in [ACCEPTANCE §5](../.ai/ACCEPTANCE.md).
- **Repository secrets actually referenced:** `AECP_PEGA_API_KEY` by [provider-environment.yml](../.github/workflows/provider-environment.yml); other provider modes rely on their real runner/home configuration. No generic production-claim secret exists.
- **Trigger:** manually dispatch **AECP Real Provider Evidence** with `source_ref=<placeholder>`, `mode=<placeholder>` selected from the workflow's actual options, `expected_arch=<placeholder>` (`any`, `x64`, or `arm64`), and only the mode-specific inputs (`model`, `local_command`, `local_args_json`, `official_model`, `pega_model`, `pega_wire_api`, `codex_worker_root`) when applicable. Run on the actual architecture-matched labeled runner; a stub or fake response is not production evidence.
- **Expected evidence:** workflow run URL, exact source SHA, emitted mode JSON and independent evidence-bundle validator PASS, provider health and worker outcome, required file-verifier/fault-isolation fields where applicable, and owner attestations for real-device/UI or Official Full MCP gates. Use [verify-evidence-bundle.cjs](../scripts/verify-evidence-bundle.cjs) for repository-side JSON checks; the three owner-record templates are under [samples/owner-evidence](../samples/owner-evidence/) and checked by [verify-owner-evidence.cjs](../scripts/verify-owner-evidence.cjs). JSON validation alone cannot prove external account ownership or service reliability.
- **Failure / rollback:** keep claim marked unverified, stop the failing provider/run, restore its owner-managed environment, and rerun from an exact SHA. Preserve the healthy worker and auth files; never silently substitute one provider for another.
- **缺口:** production credentials, model/runtime availability, supported ChatGPT workspace/connector/tunnel, real ARM64 UI and user laptop tests, and Safe Bridge external behavior cannot be established in repository-only CI. Official Full MCP remains Not ready until the full external read/write/fallback/no-DOM gate in [Blueprint/16](../Blueprint/16_CONSTRAINT_RESOLUTION_DISTRIBUTION_EXECUTION_MODES.md) is satisfied. No workflow publishes a formal production-provider certification.
