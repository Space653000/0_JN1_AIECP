## 2. 施工項 A — Reviewer 輸入完整化（20 §27 #6）

現況：`electron/lib/harness.cjs` 的 `reviewerPrompt(task, goal, done, diff, verification)` 中，`diff` 來自 `diffSummary()`（`git status --short` + `git diff --stat`，截斷 6000 字元），**沒有實際差異內容、沒有 Blueprint、沒有完整 Plan**。

改為 Reviewer 輸入包含以下四項（皆有界、皆經 `electron/lib/redaction.cjs` 遮罩、皆記錄於證據）：

1. **Blueprint**：目標 repo 有 `.ai/BLUEPRINT.md` 則用之，否則用 `Blueprint/INDEX.md`；再加該 task 引用的藍圖文件節錄（Planner 輸出可新增選填欄位 `blueprint_refs`）。總量上限建議 24 KB，並標示截斷。
2. **完整 Plan**：`aecp.plan/v1` 的全部 tasks 與相依，不只單一 task。
3. **實際 diff 內容**：worktree 相對 base 的 unified diff（含新增/刪除行），上限建議 64 KB；超過時依檔案截斷並列出「被省略的檔案與大小」；二進位檔只列名稱與大小；不得洩漏機密。
4. **Evidence**：確定性驗證結果、變更檔案清單（來自 git）、證據 manifest 的雜湊。

## 3. 施工項 B — `aecp.review/v1` Review Report（21 §7、D4）

1. 新增 `aecp.review/v1` 驗證器，欄位：`schema`、`task_id`、`run_id`、`reviewer`（provider/model）、`result`（PASS｜REWORK｜BLOCKED｜HUMAN_REQUIRED）、`blueprint`／`plan`／`implementation`／`tests`／`security`／`architecture`（各為 PASS｜WARN｜FAIL）、`findings[]`、`required_changes[]`。
2. 判定規則（決定性、在模型之外）：
   - 缺欄、格式錯誤、未知 result、非 JSON → `HUMAN_REQUIRED`（**永不為 PASS**）。
   - 任一維度為 FAIL 時 `result` 不得為 PASS；若模型宣稱 PASS，改為 REWORK 並記錄矛盾。
   - `BLOCKED` → 建立 `HUMAN_REQUIRED` 閘門並保存原因，不自動前進。
   - Verifier 未通過時，不論 Reviewer 說什麼都不得 PASS。
3. Reviewer prompt 改為要求輸出 `aecp.review/v1`。舊格式 `{result, findings, required_changes}` 視為缺少維度 → `HUMAN_REQUIRED`，並在測試中證明。
4. Review Report 持久化為任務證據（含 hash），並掛在 task 記錄上供 Dashboard（0009）投影。

## 4. 施工項 C — `aecp.worker-report/v1`（21）

Builder 執行後由 Harness 產生結構化 Worker Report：`schema`、`task_id`、`run_id`、`worker_id`、`provider`、`model`、`summary`（有界、遮罩）、`changed_files`（**來自 git，不採信 worker 自述**）、`self_reported_status`（僅供參考）。明確標示「Worker Report 不是完成證明」，完成仍只由 Verifier 證據決定；報告含 Task/Run correlation ID 並寫入證據。

## 5. 測試（TESTED）

用 fake provider 攔截 prompt，涵蓋：

- Reviewer prompt 確實含 Blueprint、完整 Plan、diff 內容、evidence；
- 超量時截斷並列出省略檔案；機密被遮罩；
- 舊格式／缺欄／非 JSON → HUMAN_REQUIRED；
- FAIL 維度 + 宣稱 PASS → REWORK；BLOCKED → HUMAN_REQUIRED 閘門；
- Verifier 失敗時 Reviewer PASS 無效；
- Worker Report 的 `changed_files` 取自 git 而非 worker 自述。

更新 `tests/harness.test.cjs` 等既有測試時**不得刪除斷言**。
