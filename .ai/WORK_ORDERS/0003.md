## 2. 施工項 A — `scripts/verify-evidence-bundle.cjs`

輸入：一個或多個 evidence JSON 路徑，加上 `--expect-sha <40碼>`、`--expect-mode <mode>`、`--expect-arch any|x64|arm64`（皆可選，但至少 SHA 必填）。檢查（每項輸出 PASS/FAIL 與原因，任一 FAIL → exit code 1）：
1. `schema === 'aecp.provider-environment-evidence/v1'`。
2. `sourceCommit` 為 40 碼且等於 `--expect-sha`。
3. `mode`、`arch`、`expectedArch` 與期望一致；`expectedArch !== 'any'` 時 `arch === expectedArch`。
4. `summary.failed === 0`（`codex-fault-isolation` mode 依 0002 B 的定義處理「預期失敗」）；每個 `checks[].status` 為合法值。
5. `privacy` 三個布林值皆為 false；並對整份 JSON 做**機密掃描**（可重用 `electron/lib/redaction.cjs`），發現疑似 token/key/Bearer/私鑰樣式 → FAIL（回報位置但不回印內容）。
6. 對 `codex-official` / `codex-pega` / `multi-codex` 相關 check：必須含 `workerId`、`model`、`health`、`codexHomeSha256`；`multi-codex` 兩個 `codexHomeSha256` 不得相同；有 `fileVerifier`（見 0002 A）者須 `expectedSha256Match === true`。
7. 標示證據來源：JSON 內無 workflow provenance 時輸出 `PROVENANCE: LOCAL_SCRIPT（非 workflow PASS）`，有則輸出 `WORKFLOW`。此欄僅供人閱讀，不改變 PASS/FAIL。

驗收（TESTED）：`tests/verify-evidence-bundle.test.cjs` 涵蓋：合法證據 PASS；SHA 不符、arch 不符、`summary.failed>0`、privacy 為 true、含偽造 `sk-`/Bearer 字串、兩個 home hash 相同、fileVerifier 不符 — 各自 FAIL。加入 `npm run check` 的語法檢查與 `npm test`；文件於 runbook「回報」段落補上「回報前先自行執行此驗證器」的指令。
