## 3. 功能 B：每個 Agent 底下的「打招呼」小介面

在每個 Agent 卡片底下加一個可收合的小區塊：

1. 模型下拉／輸入框（Ollama 顯示 `ollama list` 已安裝的模型清單——用固定、唯讀的指令，且結果經長度與字元過濾；其他 Agent 為文字輸入，預設帶目前設定值）。
2. 一顆「打招呼」按鈕。按下去才會呼叫，**按鈕本身就是這次呼叫的明確授權**（涉及網路的 Agent 在按鈕旁清楚標示「會連到網路／使用你的帳號額度」）。
3. 顯示結果：Agent 名稱、實際使用的模型、回覆文字（最多 2 KB，經 `redactSensitive`）、耗時、成功或失敗與**原因**（例如 Codex 官方的「額度用完，何時恢復」要原樣顯示，不要吞掉）。

硬性限制（防止它變成通用聊天或繞過任務流程）：

- **提示詞固定**：只送內建的一句固定問候（例如「Reply with one short greeting sentence.」），**不接受使用者自訂文字**。
- 只讀：不得在任何工作區寫檔；Codex 系列用 app 自己管理的空暫存資料夾當 cwd，沙盒維持 `workspace-write`＋`[windows] sandbox = "unelevated"`，不得改成 danger-full-access；需要時使用 Codex 官方支援的旗標讓非 git 資料夾可執行（先實測確認，並在回報寫明用了什麼）。
- 逾時 ≤ 60 秒、輸出 ≤ 2 KB、同一 Agent 同時只能有一個進行中的請求（重複按回「進行中」）。
- 走既有的 `ProviderRouter`／Worker Registry 路徑與 `policy.violation` 事件，不另開後門；呼叫要寫入 Provider usage 記錄（讓「呼叫次數」增加），但**不建立 Mission、不進任務佇列**。
- 新 IPC `agents:say-hi`（登記 `ipc-validation.cjs`，`agentId` 白名單、`model` 格式檢查）。Claude Code、Gemini、OpenCode 只有在偵測到且該 CLI 有可用的非互動模式時才顯示按鈕，否則顯示「此工具需要自行在終端機開啟」，不要為了湊功能而硬跑互動程式。
- **PEGA 需要金鑰**：沿用既有 safeStorage 存放的金鑰，由主程序在呼叫時取用；渲染端不得看到金鑰。若金鑰不存在，畫面顯示「尚未設定金鑰」而不是錯誤堆疊。
