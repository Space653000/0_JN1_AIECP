## 1. 項目 A：Codex 自動找到（依 Blueprint/08 決策 D12）

現況（已查證）：擁有者電腦上 PATH 的 `codex` 是 `C:\Users\<user>\bin\codex.cmd` 轉接檔，`command-resolver.cjs` 因為不用 shell 而找不到，畫面出現 `spawn codex ENOENT`，擁有者每次都要臨時改 PATH 才能啟動。真正的執行檔在 `%LOCALAPPDATA%\OpenAI\Codex\bin\<雜湊資料夾>\codex.exe`（該 bin 下有兩個資料夾，只有一個含 `codex.exe`，另一個只有 `rg.exe`）。

依 D12 實作，在 `electron/lib/command-resolver.cjs`：PATH 查詢找不到原生 `codex.exe` 時，才退而檢查 `%LOCALAPPDATA%\OpenAI\Codex\bin` 的**直接子資料夾**中的 `codex.exe`。條件全部要成立：是一般檔案、名稱正好是 `codex.exe`、不是連結或 reparse point、真實路徑（realpath）仍在該固定基底之下；多個候選時取最近修改者；只對 `codex` 這個指令生效；`platform !== 'win32'` 完全不變；不用 shell、不用萬用字元遞迴。找不到仍然 fail closed（維持原本的 unresolved 行為）。測試需涵蓋：正常找到、PATH 有原生 exe 時優先用 PATH、多資料夾只選含 exe 者、拒絕連結／目錄冒充／基底外路徑（含 `..` 與大小寫變化）、非 Windows 不變、既有 `tests/command-resolver.test.cjs` 全過。

## 2. 項目 B：一行指令產生真實供應商證據

擁有者目前要貼很長的 PowerShell 才能跑 `scripts/provider-environment-verify.cjs`（設 PATH、讀金鑰、設一堆環境變數）。請新增 `npm run evidence:local -- <ollama|pega|official>`（新腳本，例如 `scripts/local-provider-evidence.cjs`）：

- 以**固定的模式表**對應到既有驗證腳本的模式與環境變數，不接受任意命令；`pega` 需要金鑰時**只用不回顯的提示**（Node 的 raw-mode 讀取，不寫進檔案、不進命令列、不印出；提示前先聲明「金鑰只存在這次執行的記憶體」）；`ollama` 用 `ollama list` 讓擁有者選一個已安裝模型（固定唯讀指令，輸出過濾）；`official` 用 AIECP 自己的 `workers` 資料夾（`%APPDATA%\ai-engineering-control-plane\workers`，內含擁有者已登入的官方帳號）。
- 結果一律寫到 `artifacts/`，並在最後印出白話結論（通過／失敗＋失敗原因分類，例如「額度用完」「找不到 Codex」「沙盒拒絕寫入」），**不要只印 passed/failed 數字**。已知失敗原因請對應：Codex 官方額度用完的訊息、`ENOENT`（檔案沒被建立）、逾時。
- 明確標示這是**本機執行證據**，不是 GitHub 自架 Runner 的正式證據，也不得寫入或改動矩陣狀態。
- 測試：假 runner 證明模式表固定、金鑰不出現在任何輸出／檔案／參數、模式外的輸入被拒、失敗原因分類正確。
