## 3. 施工項 B — Diff view（22 §7）

顯示：變更檔案、新增／刪除行數、未追蹤檔、patch 大小、base commit、目前 commit、verifier 狀態。資料來自 task 記錄／證據（必要時在 Review 階段把 diff 統計存入 task 記錄，不得在 UI 端重算 git）。

## 4. 施工項 C — Review view（22 §8）

## 5. 施工項 D — GitHub view 欄位補齊（22 §9）

顯示 branch、base、commit、PR、CI status、workflow、artifacts、release、last event；取不到者一律 `UNKNOWN`。

## 6. 施工項 E — Notifications（22 §11）

六類：INFO、SUCCESS、WARNING、ACTION REQUIRED、ERROR、CRITICAL，由事件決定性映射（映射表放在測試可讀的常數）。規則：

- **不對每個 token 通知**；相同事件去重；上限建議 100 則；
- 僅顯示層可「已讀」，不改變正式狀態；
- ACTION REQUIRED 導向既有核准佇列；CRITICAL 對應政策／安全違規事件。

## 7. 施工項 F — 進度總覽（20 §16）

Planning／Implementation／Testing／Review／Acceptance 五項百分比，由 task 狀態決定性計算；**在程式與說明中寫明公式**；無 mission 時顯示 `UNKNOWN`，不得顯示假的 0% 或 100%。
