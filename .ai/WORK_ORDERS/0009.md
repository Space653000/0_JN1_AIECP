## 1. 硬性邊界

- Dashboard 只是**投影**：所有數值來自 Control Plane 正式狀態、事件帳本與 GitHub 資料，**不得自建獨立狀態**；驗證不到就顯示 `UNKNOWN`，不得造假綠燈。
- 不放寬 SecurityPolicy、不新增權限、不新增可執行動作（本單只讀取／顯示；既有的暫停／取消／STOP ALL／核准控制不得被削弱）。
- 無障礙不得倒退：不可只靠顏色表達狀態、鍵盤可達、焦點可見。保留 zh-TW／en i18n；保留「新手八問」一屏視圖。
- 不 merge PR #7、不改 `Blueprint/`。

## 2. 施工項 A — Run timeline 與 Event→Evidence（22 §6、§10）

選定 task／run 後，依事件帳本時間序列顯示 START／PREPARE／WORKER／TEST／FAIL／REWORK／PASS／REVIEW…；**點擊事件開啟該事件對應的證據**（證據路徑、雜湊、有界摘要；不倒出大檔）。每個 UI 事件必須對應一筆不可變的 Harness 事件 ID。

## 3. 施工項 B — Diff view（22 §7）

顯示：變更檔案、新增／刪除行數、未追蹤檔、patch 大小、base commit、目前 commit、verifier 狀態。資料來自 task 記錄／證據（必要時在 Review 階段把 diff 統計存入 task 記錄，不得在 UI 端重算 git）。

## 4. 施工項 C — Review view（22 §8）

以 `aecp.review/v1` 六維度（Blueprint / Plan / Implementation / Tests / Security / Architecture）與 Result 顯示；無 Review Report 時顯示 `UNKNOWN`。BLOCKED／HUMAN_REQUIRED 需明顯（文字 + 圖示，非僅顏色）。

## 5. 施工項 D — GitHub view 欄位補齊（22 §9）

顯示 branch、base、commit、PR、CI status、workflow、artifacts、release、last event；取不到者一律 `UNKNOWN`。

## 6. 施工項 E — Notifications（22 §11）

六類：INFO、SUCCESS、WARNING、ACTION REQUIRED、ERROR、CRITICAL，由事件決定性映射（映射表放在測試可讀的常數）。規則：

- **不對每個 token 通知**；相同事件去重；上限建議 100 則；
- 僅顯示層可「已讀」，不改變正式狀態；
- ACTION REQUIRED 導向既有核准佇列；CRITICAL 對應政策／安全違規事件。

## 7. 施工項 F — 進度總覽（20 §16）

Planning／Implementation／Testing／Review／Acceptance 五項百分比，由 task 狀態決定性計算；**在程式與說明中寫明公式**；無 mission 時顯示 `UNKNOWN`，不得顯示假的 0% 或 100%。
