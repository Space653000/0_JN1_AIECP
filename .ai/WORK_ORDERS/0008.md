## 2. 施工項 A — `electron/lib/repo-knowledge.cjs`

從任務的目標 repo 決定性地發現「agent 可讀的專案知識」：

1. **AGENTS.md（分層）**：根目錄，以及從任務目標／變更路徑到根的最近祖先鏈上的 `AGENTS.md`（依 `Blueprint/20` §15 的分層範例）。
2. **藍圖入口**：`.ai/BLUEPRINT.md`、`.ai/ACCEPTANCE.md`、`.ai/STATUS.md`（若存在），否則 `Blueprint/INDEX.md`。
3. **驗證指令**：`package.json` 的 `verify`／`test`／`check` scripts 名稱與指令。
4. **決策紀錄**：`Blueprint/*DECISION*` 或 `docs/**/adr*` 的檔名清單（只列名稱，不倒內容）。

輸出 `{files:[{path, sha256, bytes, truncated, included}], verificationCommands, missing:[...]}`；單檔上限建議 16 KB，總量上限建議 48 KB，逐檔遮罩，路徑須在 repo 根內。

## 3. 施工項 B — 注入方式（依 provider 能力）

- 為 provider 註冊表新增能力旗標 `discoversAgentsMd`（Codex CLI 為 true：`Blueprint/20` §15 明說應利用其 AGENTS.md 分層發現，**不要**再塞巨大 prompt）。
- `discoversAgentsMd = true`：prompt 只附簡短清單（檔名 + sha256 + 驗證指令），不附內容。
- `discoversAgentsMd = false`（例如 Ollama、其他 provider）：在 Planner／Builder／Reviewer prompt 加入有界的 `REPOSITORY KNOWLEDGE` 區塊（內容已遮罩）。
- Planner 的 CONTEXT 由「僅使用者手動提供」改為「使用者 context + 自動發現的知識」；使用者 context 仍優先、不被覆蓋。
- 每次 run 把 `repoKnowledge` manifest（不含內容，只含 path／sha256／bytes／truncated）寫入證據，供 Reviewer 與稽核重現「當時 agent 看到的知識」。
