## 1. 施工項 A — 修正證據來源標示（缺陷 F1）

現況：`scripts/verify-evidence-bundle.cjs` 依賴 `evidence.workflowProvenance`，但沒有任何程式碼寫入它，導致標示永遠是 `LOCAL_SCRIPT`。

1. `scripts/provider-environment-verify.cjs`：僅當環境變數 `GITHUB_ACTIONS === 'true'` 時，於 evidence 頂層寫入 `workflowRun: { repository, workflow, runId, runAttempt, sha }`（分別來自 `GITHUB_REPOSITORY`、`GITHUB_WORKFLOW`、`GITHUB_RUN_ID`、`GITHUB_RUN_ATTEMPT`、`GITHUB_SHA`）；本機執行不得寫入此欄位。這些都是非機密識別資訊，不得寫入任何 token（不要整包倒環境變數）。
2. `verify-evidence-bundle.cjs`：移除 `workflowProvenance`。改為：有 `workflowRun` 且欄位格式合法 → 輸出 `PROVENANCE: WORKFLOW_CLAIMED`，並印出**可直接複製的核對指令** `gh run view <runId> --repo <repository> --json headSha,conclusion,workflowName`，說明「須人工/Claude 核對輸出的 headSha 等於 evidence.sourceCommit 且 conclusion 為 success，驗證器本身不聯網」；無 `workflowRun` → 維持 `LOCAL_SCRIPT（非 workflow PASS）`。另外，`workflowRun.sha` 存在且不等於 `sourceCommit` → FAIL（欄位矛盾）。此標示不得單獨改變其他檢查的 PASS/FAIL 語意（除上述矛盾檢查外）。
3. 同步 `tests/verify-evidence-bundle.test.cjs`（涵蓋：無 workflowRun → LOCAL_SCRIPT；合法 workflowRun → WORKFLOW_CLAIMED 且輸出含 gh 指令；workflowRun.sha 與 sourceCommit 不符 → FAIL；`workflowRun` 含疑似機密 → 既有機密掃描 FAIL）、`tests/provider-environment-workflow.test.cjs` 或對應測試（涵蓋 script 在 `GITHUB_ACTIONS=true` 與非 Actions 環境下的欄位有無）。
4. 更新 `Reports/ENVIRONMENT_EVIDENCE_RUNBOOK.md` 共通規則：說明兩種標示的意義與核對指令。

驗收（TESTED）：上述測試通過；`npm run verify` 全綠。
