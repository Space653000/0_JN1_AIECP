## 1. OpenCode：用真正的清單指令（比別名更好）

已查證：`opencode --help` 顯示有 `opencode models [provider]`，官方說明是「list all available models」，是一個唯讀、會列出真實清單的指令，不是猜測出來的別名。

- 比照 `ollama list` 現有的做法（0019 的 Ollama 模型下拉選單），新增一個唯讀、固定參數的呼叫 `opencode models`（不帶任何使用者輸入的參數，避免注入），解析輸出得到模型清單，顯示為下拉選單；解析失敗或指令不存在時，回退成現有的自由輸入框並在旁邊註明「無法取得清單，請手動輸入」，不要讓整個卡片壞掉。
- 若清單格式包含 `provider/model` 這種路徑（旗標說明是 `-m, --model <provider/model>`），下拉選單的值需與 `--model` 實際吃的格式一致；用一小段解析函式並寫測試證明轉換正確，不要憑感覺拼字串。
- 若目前設定值不在清單中（例如舊設定），下拉選單顯示「自訂」並把原值帶進一個文字框，不遺失既有設定（比照 0021 對 Claude Code 的做法）。
- 呼叫 `opencode models` 要有逾時與輸出上限（比照現有 Ollama 清單呼叫的限制），失敗不得拋出未捕捉例外。

## 回報

### OpenCode 做了什麼
新增 `parseOpenCodeModels`（`electron/lib/agent-settings.cjs`），解析真實 `opencode models` 的輸出，只保留符合模型名稱格式的行（`provider/model` 形式，剛好就是 `--model` 旗標吃的格式，不需要任何轉換）。`electron/main.cjs` 新增 `listOpenCodeModels()`：固定呼叫 `opencode models`（不帶任何使用者輸入的參數）、8 秒逾時、512 KB 輸出上限（沿用 `execFixed` 既有限制）。解析失敗、指令不存在、逾時或輸出裡沒有任何看起來像模型的行，都會回退成現有的自由輸入框，並在旁邊顯示「無法取得清單，請手動輸入」，不會讓整張卡片壞掉。若目前設定值不在清單中，下拉會顯示「自訂」並把原值帶進文字框（比照 0021 對 Claude Code 的做法）。已在這台電腦上用真的 `opencode models` 測過，會列出這台機器上 OpenCode 目前看得到的模型（例如 `opencode/big-pickle`）。

### Gemini CLI 有沒有查到官方支援
有查證（這台機器沒有直接裝 `gemini`，但用 `npx @google/gemini-cli --help` 直接叫到了官方套件的說明）。結果：`-m/--model` 只接受一個自由字串，**沒有**任何官方維護的別名（不像 Claude 有 sonnet／opus／fable），也**沒有**任何「列出可用模型」的子指令（`gemini gemma` 是本機 Gemma 路由設定，跟列模型是兩回事）。所以照施工單的指示：**維持現狀的自由輸入框，不做假清單**，並在卡片加上一句「此工具沒有可自動偵測的模型清單，請手動輸入」，讓你知道這不是還沒做完，而是這個工具本來就沒有東西可以列。

### Codex CLI、ChatGPT 網頁版為什麼刻意不動
Codex CLI 的通用偵測卡片只顯示版本，本來就沒有模型設定或打招呼——真正要用 Codex 一律走 Codex OFFICIAL／PEGA 卡片，這兩個已經在 0019／0021 處理過。ChatGPT 網頁版依 Blueprint 的邊界，AIECP 不注入、不控制官方網頁，所以它本來就沒有設定欄位，這兩個都照施工單的要求原封不動。

### 測試與破壞紀錄
新增 `tests/opencode-known-models.test.cjs`，7 個測試：解析函式只留下合法的 `provider/model` 行、`--model` 旗標原封不動接收清單給的值、真的透過主程序呼叫確認參數固定＋有逾時＋有輸出上限、指令不存在／出錯／輸出是空的／輸出沒有斜線時都優雅回退不拋例外、既有的自訂值在清單可用時仍正確顯示為自訂、清單拿不到時顯示自由輸入框與說明文字、Gemini CLI 沒有清單且顯示它自己的說明文字。破壞紀錄 5 筆（拿掉格式檢查、讓失敗也回傳空清單、拿掉主程序附加 `knownModels` 的邏輯、拿掉清單不可用時的說明文字、拿掉 Gemini 的固定旗標），全部 DETECTED。Claude Code（0021）、PEGA、Codex OFFICIAL、Ollama、Codex CLI、ChatGPT 網頁版的既有測試斷言沒有改動。
