## 0. 為什麼

擁有者喜歡 ChatGPT 與 Codex 桌面版的顏色與版面，要求 AECP 的網頁與所有呈現給人看的介面盡量仿照。參考已完成的範例：`artifacts/dashboard/index.html` 的 `<style>` 區塊（深色近黑中性底、柔和圓角卡片、單一綠色強調、等寬字體用於程式碼與 ID、淺色主題為白底與淺灰卡片）。

## 1. 範圍

- **只改視覺**：`ui/styles.css`（與必要時 `ui/index.html` 的版面容器／class，不改任何 `id`、`data-*`、`aria-*`、`data-i18n` 與既有 class 名稱，避免破壞既有 UI 測試與腳本）。**不改任何功能行為、IPC、權限。**
- **色彩 token 化**：所有顏色改由 `:root` 的 CSS 變數決定（若還沒有），並定義兩組主題：
  - 深色（預設，跟隨系統）：背景 `#212121`、卡片 `#2f2f2f`、次要面 `#3a3a3a`、邊線 `#424242`、文字 `#ececec`、次要文字 `#b4b4b4`、強調綠 `#19c37d`；狀態色：成功綠、警告琥珀 `#f5b74f`、錯誤紅 `#ff6b6b`。
  - 淺色：背景 `#ffffff`、卡片 `#f7f7f8`、邊線 `#e5e5e5`、文字 `#0d0d0d`、次要文字 `#6e6e80`、強調綠 `#10a37f`。
  - 保留既有的 `data-theme` 與 `ui/theme.js` 的 system／dark／light 行為，只換 token 值。
- **版面風格**：窄置中的內容欄（約 860px 以內）、卡片圓角 12–16px、細邊線、大留白、按鈕與標籤為圓角膠囊、輸入框圓角並有柔和聚焦環、等寬字體用於 ID／程式碼／路徑；側邊面板可維持現有結構，但外觀比照 Codex 的左側欄（暗色、無粗邊框、選中項用低對比底色高亮）。
- **商標與品牌邊界（必守）**：**只仿顏色與版面感覺，不使用 OpenAI／ChatGPT／Codex 的標誌、字標、圖示或字型檔。** 藍圖 01 規定 AECP 自己的名稱與識別必須比任何供應商更醒目；不要出現會讓人以為是 OpenAI 產品的文字或圖示。

## 2. 無障礙與測試（不得倒退）

- 深色與淺色兩組主題中，一般文字與背景對比 **≥ 4.5:1**、大字與元件邊界 **≥ 3:1**；狀態不得只靠顏色（保留文字或圖示）；鍵盤焦點可見；`prefers-reduced-motion` 仍生效。
- 新增測試 `tests/ui-theme-contrast.test.cjs`：**解析真實的 `ui/styles.css`** 取出兩組主題的 token，用 WCAG 公式計算下列配對的對比並斷言達標：文字／背景、次要文字／背景、次要文字／卡片、強調色（用於文字時）／背景、三種狀態色／卡片。破壞紀錄：把某個 token 改成低對比值（例如把深色文字改成 `#555555`），測試必須失敗。
- 既有測試（`dashboard-visibility-ui`、`theme-behavior`、`i18n-accessibility`、`electron-shell-and-modes` 等）全部照過，不改斷言。
- 用 `npm start`（若本機有 Electron）或 `ui/` 加假 bridge（可參考 `tests/support/ui-harness.cjs`、`artifacts/ui-check/serve.cjs`）在瀏覽器實際看過深色與淺色兩種畫面；**在回報附上你看到的描述**（哪些區塊、哪些狀態、有沒有版面跑掉）。
- 矩陣：把 `B01-A11Y-L172`（4.5:1 對比）的 `note` 更新為「token 對比已由自動測試驗證；已安裝應用程式的實機觀察仍為 MANUAL」，**狀態維持 MANUAL**（你不能替它結案）。
