## 1. 項目（依序，安全優先）

**A. `CODEX_HOME` 隔離（G15①，安全，B03-L56）** — `electron/lib/worker-registry.cjs` `canonicalHome`／`register`：以 `fs.realpath`（目錄不存在時對最近的既有祖先做 realpath 再接續其餘片段）與 Windows 大小寫正規化比較；拒絕相同、junction／symlink 別名、巢狀在另一個 worker home 內、以及是另一個 worker home 的上層目錄。測試涵蓋這四種與大小寫（僅 Windows）、且兩個不相交的 home 仍可註冊。

**B. 資源憑證外洩（G11③，B05-L20）** — `electron/lib/resource-manager.cjs` `scan`：寫入 `resources.json`、事件與 planner prompt 之前，把 remote URL 內嵌的 `user:password@`／token 移除（重用 `redaction.cjs` 的 URL 規則），保留可用於辨識 repo 的 host/path。測試用 `https://alice:ghp_xxx@github.com/o/r.git`，斷言檔案與 prompt 皆不含 `ghp_`／`alice:`。

**C. Worker 健康檢查不驗證端點（G15②，B03-L68）** — `electron/lib/provider-router.cjs` `health`（codex-cli worker 分支）：在網路已核准時，對 `baseUrl` 做一次**有界、無憑證**的探測，判定所選 `wire_api`（responses／chat）是否為端點支援；不通就回 `DEGRADED`（附原因碼，不含網址參數）。網路未核准仍不發請求。測試用本機 loopback 假端點（支援／不支援／逾時三種）。

**D. 鎖回收沒有釋放原因（G11④，B02-L109）** — `electron/lib/lock-manager.cjs` `_recoverUnlocked`：回收時記錄 `{key, owner, reason:'EXPIRED', expiredAt}`，並回傳給呼叫端；維運事件寫入每把鎖的原因（不含機密）。

**E. 跨倉庫鎖順序（G11⑤，B05-L88）** — `electron/lib/control-plane.cjs` `taskMutationLockKeys` 與取鎖處：多把鎖以**穩定排序**取得；取不到時以 `BLOCKED`（附鎖 key 與持有者）失敗，不再默默退回 QUEUED。測試用兩個任務以相反順序要同樣兩把鎖，證明不會死結。

**F. 同 repo 兩任務並行（G13）** — `git-admin` 鎖改為**有界等待重試**（例如最多 10 秒、指數退避），逾時才失敗；證明兩個同 repo 任務同時派發都能完成。

**G. 孤兒 worktree 清理（G14，R5.4）** — (1) 清理目標的 repo 根目錄用該任務實際綁定的 repo（不要用 `run.sourceRoot` 容器目錄）；(2) 每輪維運最多處理 N 個（預設 20），並跳過目錄已不存在且 git 登記已清除的項目，剩餘留待下一輪。測試用兩個 repo 的 Mission，並用 60 個已不存在的項目證明每輪 git 呼叫有上限。

**H. 損毀狀態檔不得讓 App 無法啟動（G16，R3.6）** — `electron/main.cjs` `initControlPlane` 路徑：`worker-registry.json`／`control-plane.json` 損毀時，把損毀檔改名為 `*.corrupt-<timestamp>` 保留、以空狀態啟動、記錄事件並讓 UI 顯示警告，**先註冊 IPC 再初始化 Control Plane** 或確保初始化失敗時仍註冊 Safe Bridge 所需的 handler。測試用真 `main.cjs`（假 electron）：損毀後 Safe Bridge 仍可用。

**I. 預算預設值失效（G15③）** — `electron/lib/control-plane.cjs` `createMission`：省略（`undefined`／`null`）的預算使用預設公式，不再被 `clamp(null)` 退化成 1。測試：省略 `maxTurns`／`maxFailedAttempts` 得到預設值，明確傳 0 或負數仍被夾到下限。
